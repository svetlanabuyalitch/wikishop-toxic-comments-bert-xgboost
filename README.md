# «Викишоп»: классификация токсичных комментариев

Бинарная классификация комментариев к товарам: токсичный (1) / нетоксичный (0). Цель — автоматически отправлять токсичные комментарии на модерацию.

## Данные

- 159 292 комментария, поля `text` и `toxic`; ~10.2% токсичных.
- Удалены 46 неявных дубликатов (различие только в регистре/пробелах) — устранена утечка данных, в том числе один случай противоречивой разметки.
- Файл `toxic_comments.csv` в репозиторий не входит.

## Подход

1. Тексты → 768-мерные BERT-эмбеддинги (`bert-base-uncased`, CLS-токен, `max_length=128`), CPU, ~2.4 часа на train.
2. Сравнение 7 алгоритмов на 3-fold `StratifiedKFold`.
3. Порог классификации подбирается по out-of-fold предсказаниям (`precision_recall_curve`), а не на тесте — оценка без утечки.

## Результаты кросс-валидации

| Модель | F1 (порог 0.5) | F1 (подобранный порог) | Время |
|---|---|---|---|
| **XGBoost** | 0.701 | **0.7014** | 265 с |
| LightGBM | 0.691 | 0.6909 | 110 с |
| GradientBoosting | 0.665 | 0.6652 | 8875 с |
| LinearSVC | 0.641 | 0.6411 | 58 с |
| LogisticRegression | 0.641 | 0.6408 | 34 с |
| DecisionTree | 0.498 | 0.4981 | 126 с |
| RandomForest | 0.473 | 0.4726 | 202 с |

**Тест (XGBoost, порог 0.499):** F1 = **0.6930**, precision 0.639, recall 0.757, accuracy 0.932.

Целевое значение F1 ≥ 0.75 **не достигнуто**. Причины и план улучшений — в последнем разделе ноутбука: fine-tuning BERT вместо замороженных эмбеддингов, гибрид с TF-IDF по n-граммам, порог с учётом стоимости ошибок.

## Запуск

```bash
pip install -r requirements.txt
jupyter notebook wikishop_toxic_comments_bert_xgboost.ipynb
```

Эмбеддинги сохраняются в `feat_train_toxic.npy` / `feat_test_toxic.npy` — повторный прогон классификаторов не требует BERT.
